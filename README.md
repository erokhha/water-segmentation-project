## 1. Задача и требования

### Исходная формулировка задания

> «Исходные данные — снимок с КА ДЗЗ с разрешением 0,5 м. Без геопривязки.  
> Задание: Распознавание объектов — выберите один или несколько классов объектов, часто встречающихся на снимке (корабли, здания, водная поверхность и т.д.).  
> Цель — выполните распознавание этих объектов на всём снимке. Результат — векторный слой объектов выбранного класса.  
> Цели задач достигаются на основе применения моделей машинного обучения/нейронных сетей.  
> Ручной поиск/привязка и разметка допускается только для контроля результата. Инструментарий выполнения заданий не ограничивается.»

### Наш выбор

**Выбранный класс:** `water` (водная поверхность).  
**Тип задачи:** бинарная семантическая сегментация. Это означает, что модель определяет для каждого пикселя, относится он к воде (`1`) или нет (`0`).  
**Результат:** полигоны водной поверхности в векторном файле GeoPackage (`.gpkg`), пригодные для проверки и наложения на исходное изображение в локальных координатах.

### Обязательные условия

- Обработать **всю площадь** исходного изображения; не ограничиваться несколькими примерами.
- Использовать **модель машинного обучения** для выделения воды, а не ручную обводку.
- **Самостоятельно дообучить** модель с предобученным энкодером на **открытых размеченных данных**. Это дополнительно зафиксированная учебная цель проекта.
- **Не использовать ручную разметку целевого TIFF для обучения** или подбора параметров. Такая разметка допустима только для независимого контроля готового результата.
- Не выдумывать географическую привязку, координаты на Земле или EPSG-код.
- Сохранять воспроизводимость: фиксировать данные, параметры, версии библиотек, веса и результаты проверок.

### Что не входит в проект

- Поиск местоположения снимка на Земле и геопривязка.
- Распознавание видов судов и других отдельных классов.
- Создание географической карты с реальными координатами без дополнительных исходных данных.
- Ручная разметка целевого снимка как замена работе нейросети.

## 2. Что известно об исходном снимке

Сведения о размере и формате получены из предоставленных автором данных, затем **подтверждены выводом `src/inspect_tiff.py`** на исходном файле.

| Свойство | Значение |
|---|---|
| Формат | TIFF |
| Размер | **21 156 × 13 714 пикселей** |
| Размер файла | **870 401 156 байт** (приблизительно 870 МБ) |
| Каналы | **3**, в порядке Red / Green / Blue |
| Тип значений | `uint8`, по **8 бит на канал** |
| Заявленное разрешение на местности | **0,5 м/пиксель** (со слов автора задания; не проверено по геопривязке) |
| Географическая система координат (`CRS`) | **Отсутствует (`None`)** |
| Геопривязка, контрольные точки, RPC | **Отсутствуют** |
| Сжатие | **Нет** |
| Внутренние блоки TIFF | `(128, 21156)` по каждому из трёх каналов |
| Место содержания | Береговая/лагунная зона, море, острова, порты, город, каналы, отмели, суда, тени |

При открытии Rasterio выдаёт `NotGeoreferencedWarning`. **Для этого файла предупреждение ожидаемо и не означает, что TIFF повреждён.** Возвращаемое преобразование координат является единичным, а не реальной географической привязкой.

Исходный файл хранится локально у владельца проекта, пример пути в работе:

```text
/путь/к/исходному_снимку.tif
```

**Не считать этот путь универсальным:** у другого разработчика файл может находиться в другом месте. TIFF не нужно без необходимости копировать в Git-репозиторий.

## 3. Что считается водой

Целевой класс определён как **видимая водная поверхность** независимо от цвета, глубины и прозрачности.

| Участок | Требуемая метка |
|---|---|
| Море, река, озеро, лагуна, канал | `water = 1` |
| Мелководье, через которое видно дно, но поверхность покрыта водой | `water = 1` |
| Обнажённый песок, ил, берег, суша, остров | `not water = 0` |
| Различимые корабли, лодки, мосты, причалы, здания, перекрывающие воду | `not water = 0` |
| Тень на уверенно определяемой водной поверхности | `water = 1` |
| Поверхность, чей тип достоверно определить нельзя | `ignore` **в контрольной разметке**, а не автоматически `not water` |
| Бассейн с видимой водой | Предварительно `water = 1`; окончательно уточняется при проверке правил датасетов |

**Важное требование:** отдельные объекты внутри акватории должны оставаться отверстиями в водной маске там, где они различимы на снимке. Не заполнять автоматически все небольшие отверстия при постобработке.

**Ограничение:** очень маленькие лодки могут занимать считанные пиксели. Их безошибочное исключение нельзя гарантировать только выбором U-Net; нужна проверка содержания обучающих масок и итогового качества.

## 4. Выбранный метод и устройство решения

### Модель

- **Архитектура:** **U-Net** для семантической сегментации.
- **Энкодер:** **ResNet-34**. Это часть сети, извлекающая признаки изображения.
- **Исходные веса энкодера:** предобучение на **ImageNet**.
- **Задача на выходе:** **один канал**, задающий оценку принадлежности пикселей к воде.
- **Библиотека:** `segmentation-models-pytorch` поверх PyTorch.
- **Обучение:** самостоятельно на подходящих открытых масках воды; готовая модель сегментации воды не подменяет собственное обучение.

Предварительная конфигурация, **ещё не использованная для полноценного обучения**:

```python
import segmentation_models_pytorch as smp

model = smp.Unet(
    encoder_name="resnet34",
    encoder_weights="imagenet",
    in_channels=3,
    classes=1,
)
```

### Обучение

```text
Открытые RGB-снимки и готовые разметки
                ↓
Проверка соответствия масок нашему классу water
                ↓
Разделение по независимым снимкам / географическим участкам
                ↓
Бинарные метки water=1, not-water=0 + маска допустимых пикселей
                ↓
Фрагменты для обучения (стартовый размер 512×512)
                ↓
U-Net + ResNet-34 (веса энкодера ImageNet)
                ↓
Функция ошибки + обновление весов
                ↓
Проверка на Validation и выбор лучшей модели
                ↓
Сохранённые веса и параметры обучения
```

Начальная функция ошибки: **BCEWithLogitsLoss с исключением неизвестных пикселей** (`valid_mask`). Это **план**, не реализованный код. Позднее можно сравнить с Dice/BCE+Dice, только если это действительно нужно.

### Применение к целевому снимку

```text
Исходный TIFF 21156×13714
            ↓
Rasterio читает окна без уменьшения исходного изображения
            ↓
Подготовка RGB ровно в том виде, который ожидает обученная модель
            ↓
U-Net возвращает оценки принадлежности к воде для каждого окна
            ↓
Объединение оценок в перекрывающихся частях окон
            ↓
Порог, выбранный по Validation → единая бинарная маска
            ↓
Преобразование водных областей в полигоны
            ↓
GeoPackage + растровая маска + отчёт о качестве
```

**Начальные параметры оконной обработки (подлежат проверке):**

| Параметр | Значение |
|---|---:|
| Размер окна | `512 × 512` пикселей |
| Перекрытие | `128` пикселей |
| Шаг перехода | `384` пикселя |
| Число окон для нашего размера при полном покрытии | Приблизительно **1980** |

Нейросеть получает все области TIFF. Количество окон определяется автоматически; **не нужно заранее сохранять тысячи отдельных файлов**. На краях окна корректируются так, чтобы не осталось необработанных пикселей. Оценки соседних окон объединяются **до** получения бинарной маски.

### Векторные координаты

У TIFF нет географической привязки. Поэтому итоговый слой будет представлен **в локальных координатах изображения**, без географического EPSG.

Предлагаемая договорённость для совместного просмотра растра и вектора:

```text
Начало координат: верхний левый угол изображения
X: вправо, в пикселях
Y: вверх, в пикселях (Y = −номер строки)
Единица: пиксель, не метр и не градус
Географическая привязка: отсутствует
```

Это соглашение **ещё не реализовано и не проверено в QGIS**. Для правильного наложения и растр, и вектор должны использовать одинаковую локальную систему. Геометрия должна сохранять отверстия: острова, причалы и различимые суда не должны превращаться в воду из-за автоматического заполнения дыр.

## 6. Обучающие данные и правила работы с ними

### Основной кандидат: OpenEarthMap

- Открытый набор высокодетальных RGB-аэроснимков и спутниковых изображений.
- **5000 изображений**, **8 классов**, включая `water`.
- Разрешение **0,25–0,5 м/пиксель**.
- Данные из **97 регионов, 44 стран**.
- Изображения и разметка предоставлены авторами; **условия лицензии зависят от исходного источника каждого участка**.
- RGB-изображения части xBD **не входят в основной архив OpenEarthMap** и при необходимости загружаются отдельно.

Официальный архив: <https://zenodo.org/records/7223446>  
Официальный код: <https://github.com/bao18/open_earth_map>  
Описание источников/лицензий: <https://open-earth-map.org/attribution.html>

**Критическая проверка перед обучением:** как в реальных масках OpenEarthMap отмечены корабли, лодки, причалы, острова, мосты и мелководье. Наличие класса `water` само по себе **не гарантирует** нужной детализации внутри акватории.

### Дополнительные кандидаты, если потребуется

| Набор | Возможная роль | Ограничение |
|---|---|---|
| **FLAIR-HUB** | Прибрежные/городские участки, дополнительные примеры воды | Отличается разрешение; подбирать RGB и соответствующие маски; объём полного набора велик |
| **iSAID** | Разметка отдельных судов как примеров `not water` | Нет полноценной семантической маски воды; понадобится отдельная логика использования |
| **LoveDA** | Резерв для городской среды | Неизвестно, подходят ли правила разметки для маломерных судов |
| **GLH-water** | Потенциальный специализированный набор воды | Требуется проверка лицензии и масок на объектах внутри воды |
| **CAID** | **Не включаем в прямое обучение при текущем определении Water** | По опубликованным правилам некоторые малые лодки/плавучие доки относятся к воде, что противоречит нашей цели |
| **LandCover.ai** | Не добавлять к OpenEarthMap автоматически | Часть его изображений используется в OpenEarthMap; риск дублирования |

Ссылки: [FLAIR-HUB](https://ignf.github.io/FLAIR/FLAIR-HUB/flairhub.html), [iSAID](https://captain-whu.github.io/iSAID/dataset.html), [LoveDA](https://github.com/Junjue-Wang/LoveDA), [CAID](https://github.com/lubyant/CAID).

**Не скачивать все наборы сразу.** Начать с OpenEarthMap, проверить качество разметки и провести один базовый эксперимент. Дополнительные данные вводить только при понятной необходимости.

### Правила подготовки разметки

1. Сначала проверить оригинальные классы и значения масок в **реальных файлах**, а не назначать число для `water` по предположению.
2. Преобразовать корректно размеченную воду в `1`, другие достоверно известные классы в `0`.
3. Неизвестные / `no-data` пиксели отмечать отдельной **маской допустимости (`valid_mask`)**; не выдавать их за сушу.
4. Делить данные на **Train / Validation / Test по независимым исходным снимкам или географическим участкам**, а **не** случайно по соседним нарезанным кускам.
5. Для обучения использовать только размеченные открытые наборы. Целевой TIFF **не входит** в Train и Validation.
6. Фиксировать версии и происхождение файлов, правила объединения классов и все преобразования размеров.
7. Не применять к маскам классов обычную интерполяцию цвета; при изменении их размера использовать подходящую интерполяцию без появления дробных номеров классов.

## 10. Как будем оценивать качество

**На OpenEarthMap:** Train служит для обучения; Validation для настройки модели и порога; Test для независимой оценки готовой конфигурации. Разбиение выполняется по независимым исходным сценам/регионам, чтобы соседние фрагменты одного места не попали одновременно в обучение и тест.

**На целевом TIFF:** контрольная ручная разметка допускается только для проверки готового результата. Нельзя использовать эти метки для изменения весов или порога и затем считать тот же участок независимым тестом.

Планируемые показатели:

| Проверка | Что показывает |
|---|---|
| **IoU для воды** | Насколько предсказанная площадь воды совпадает с эталоном |
| **Precision воды** | Какая доля предсказанных водных пикселей действительно вода |
| **Recall воды** | Какая доля эталонных водных пикселей найдена моделью |
| **Контроль границ** | Ошибки на берегах, в узких каналах и на мелководье |
| **Контроль исключаемых объектов** | Не закрашены ли водой лодки, мосты, причалы и острова |
| **Контроль окон** | Нет ли необработанных пикселей и заметных швов |

Нельзя заранее обещать конкретный процент точности. Для этого пока нет результатов на исходном снимке. Также высокий IoU всей воды сам по себе не означает правильного выделения маленьких лодок.

## 11. Ограничения и риски

1. **Перенос между датасетом и целевым снимком:** в целевом TIFF есть морская/лагунная вода, отмели и порты, которых может не хватать в открытых данных. *Проверка: анализ масок и раздельная оценка по типам местности.*
2. **Правила разметки судов:** известен риск, что некоторые датасеты называют водой область под мелкими лодками. *Проверка: открыть нативные пары изображение/маска до обучения.*
3. **Мелкие объекты:** суда и узкие сооружения могут занимать очень мало пикселей. *Проверка: отдельный контроль, без обязательного заполнения отверстий в маске.*
4. **Разрешение и масштаб:** датасеты с одинаковым размером фрагмента могут иметь разный GSD. *Проверка: учитывать физический масштаб, не уменьшать целевой TIFF целиком.*
5. **Разметка и утечки:** соседние изображения нельзя случайно разводить между Train и Test. *Проверка: разделять исходные регионы до нарезки.*
6. **Производительность MPS:** маленький шаг обучения не доказывает скорость длительного обучения. *Проверка: короткий реальный запуск и замер времени.*
7. **Отсутствие геопривязки:** нельзя выдавать локальные пиксельные координаты за координаты на Земле. *Проверка: отсутствие придуманного EPSG и корректное совмещение в локальной системе.*
8. **Объём полигонов:** шумная маска может породить очень много мелких геометрий. *Проверка: пробная векторизация; не упрощать границы без контроля.*
9. **Лицензии:** условия использования исходных изображений OpenEarthMap зависят от источника. *Проверка: реестр использованных файлов и атрибуция.*

## 12. Инструкции для нового разработчика или ИИ-ассистента

**Сначала прочитайте этот README и проверьте реальное состояние папок и окружения. Не начинайте проект заново.**

Правила совместной работы:

- Работать **по одному этапу**, объясняя простыми словами: что делаем, зачем, какие команды выполнить и как понять, что получилось. Не переходить к следующему этапу без подтверждения автора проекта.
- **Не заменять** согласованную U-Net/ResNet-34 на другую архитектуру без конкретной причины и согласования.
- **Не подменять собственное обучение** применением полностью готовой модели сегментации воды.
- **Не вводить лишнюю универсальность**: наш диагностический скрипт читает данные Rasterio и сохраняет фрагменты; обработку входов для нейросети реализовать отдельно.
- Не придумывать сведения о лицензиях, кодах классов, метриках или результатах запуска. Сверять значимые технические решения с первоисточниками.
- Считать выполненным только то, что подтверждено запуском, файлом или явным сообщением владельца.
- При ошибке исправлять конкретную причину, а не переустанавливать всё наугад.
- Не использовать ручную разметку целевого TIFF для обучения, подбора порогов или подгонки к контрольным участкам.
- Не менять исходный TIFF и не добавлять его в публичный репозиторий без явного разрешения.
- Поддерживать чек-лист и дату актуальности этого README после каждого завершённого этапа.

### Что важно для нового участника

- Существующий `src/inspect_tiff.py` является **только диагностикой** и сохраняет пять примеров. Он **не выполняет** полную нарезку и сегментацию.
