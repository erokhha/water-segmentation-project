# Дополнительный Train GLH-Water + Coast Train

Статус: **экспериментальный Train для запуска владельцем после проверки preflight**.
Семантический просмотр каждой границы маски и условия использования GLH
остаются незакрытыми; это не допуск данных для итоговой модели или публикации.

`base_4023/` — побайтная копия зафиксированного набора
`configs/trial_train_tyrolw_20261101_001/` до добавления внешних источников.
Исходный набор и текущее обучение не изменялись.

Целевой состав по решению владельца: 4023 прежние пары, затем до 700 новых
фрагментов 512×512 из авторского Train GLH-Water и до 700 из NAIP-6/NAIP-11
Coast Train. Первые примерно 400 фрагментов каждого источника отбираются по
типам трудных сцен; остальные — по ошибкам одного фиксированного checkpoint
после завершения текущего обучения. Перекрытие окон Coast допустимо только
после проверки почти повторов. Иные источники и OEM Test не используются.

Реестр источников, проверок и кандидатов хранится в
`outputs/checks/glh_coast_intake_20261101_001/`. Наличие RGB и маски в
каталоге проверки не означает допуска пары в обучающий manifest.

`proposed_train_manifest.csv` содержит 5423 кандидатные строки: исходные 4023
+ 700 GLH + 700 Coast, со ссылками на каталог аудита. В `train_manifest.csv`
те же 5423 идентичности, но пути новых пар ведут в отдельный стабильный
`data/processed/glh_coast_train_20261101_001/` (3500 файлов). Этот manifest
читает `src/continue_glh_coast_from29.py`; контрольные суммы всех
1400 внешних RGB, масок и valid-масок зафиксированы в
`external_files_sha256.csv`, контракт — в `manifest.json`. Старый
`hard_train_data.py` сам по себе два новых источника не поддерживает; новый
загрузчик `src/glh_coast_train_data.py` использует его только для прежних 4023
пар. Текущий `train_manifest.csv` исходного набора и прежнее обучение не
менялись.

GLH: 393 типовых фрагмента и 307 фрагментов по ошибкам одного замороженного
checkpoint из 58 исходных сцен. Сцена 64 исключена полностью: исходная маска
не отделяет достоверно воду от отмелей на нескольких показанных участках.
Сцены 54 и 98 исключены ранее по известным расхождениям. GLH-маски содержат
только 0/255; локального `unknown` нет. Права на производные фрагменты и
обучение не указаны явно на авторской странице.

Coast: 380 типовых фрагментов и 320 по ошибкам замороженного checkpoint из
112 NPZ (99 прокси исходных съёмок). NAIP-6 не использовался: подлинный RGB
для него не подтверждён. В NAIP-11 `sediment`, `nodata` и чёрный RGB исключены
из обучаемых пикселей через отдельную `valid`-маску. 13 окон с менее чем 50%
действительных пикселей и один спорный по визуальному хешу кадр не вошли.
Два этапа Coast имеют перекрывающиеся окна, но ни одна пара из одного файла
не перекрывается на 75% или более. Краткая процедура и ограничения записаны
в `outputs/checks/glh_coast_intake_20261101_001/error_selection_protocol.md`.

Для второй части отобран полный checkpoint эпохи 29 текущего 30-эпохового
запуска только по IoU неизменной OEM Validation при пороге 0,65. Это правило
нужно для поиска ошибок на внешних парах, а не для принятия новой модели.
Целевой TIFF и OEM Test в отборе не использовались.

Для пробного дообучения владельцем задано 40 новых эпох от полного checkpoint
локальной эпохи 29 вместе с её AdamW. Прежние настройки loss и Validation
сохраняются. Новый загрузчик и скрипт запуска проходят синтетические тесты и
реальный `--preflight` с MPS, без шага обучения. Каждый спорный пиксель 1400
внешних масок вручную не подтверждён, а явные условия GLH пока не установлены.
Полученные веса будут только кандидатами, требующими отдельной оценки.
