Файлы: `train_manifest.csv` — общий список пяти источников; `oem_train.csv` — OEM-часть для `WaterDataset`; `oem_val.csv` — новая диагностическая OEM Validation; `manifest.json` — точные ID, хеши и происхождение. 18 тайлов `tyrolw` остаются в новой Validation. Все 7 тайлов, помеченные Validation в оригинальном OpenEarthMap, и примыкающие к ним тайлы остались вместе. Между перенесёнными и оставленными тайлами минимум 300 м по границам TIFF. Весь регион всё ещё может происходить из одной съёмки: новая Validation не является независимой оценкой переноса на другую местность.

**Прежнюю Validation из 402 сцен после обучения на этом Train нельзя использовать целиком как независимый контроль:** 31 её `tyrolw`-тайл теперь вошёл в Train. Для сравнения моделей можно заново оценить обе на одном и том же непересекающемся наборе, отдельно показав `tyrolw`; для независимого вывода о переносе нужен другой ранее не использованный контроль. На новой `oem_val.csv` можно смотреть диагностические ошибки, но её общую метрику нельзя напрямую сравнивать со старыми 402 сценами.

Старые обучающие скрипты привязаны к frozen составу 4000 и **не используют** эту версию автоматически. Отдельный подготовленный entrypoint — `src/continue_hard_tyrolw_neg11.py`. Он строго загружает полный checkpoint прежней эпохи 20 вместе с AdamW, использует эти 4023 пары, вес суши 1,1, прежние LR/порог/BN и 371-сценную диагностическую Validation. Его MPS preflight прошёл; обучение владелец запускает отдельно командой из [VAL подготовки](../../docs/s2tdd/validation/VAL-TYROLW-NEG11-CONTINUE30-PREP-001.md). Эта версия данных сама по себе не меняет loss, optimizer или порог.
